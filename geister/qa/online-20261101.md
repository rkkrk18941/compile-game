# Geister online entry — 2026-11-01

## Problem and change

The earlier CDN/loading fix still used direct WebRTC data channels. Signaling could succeed while the actual host/guest data connection never opened. The inherited HTTPS prototype had not been committed to main.

Normal online games now default to authenticated HTTPS messages through the collection's existing Firebase project and existing permissions. The host remains authoritative, and each guest receives only its own engine view. The four-character code and canonical game URL stay unchanged. PeerJS remains available explicitly with `?net=peer`; BroadcastChannel test mode remains `?net=local`.

Tournament rooms use eleven independently permissioned host/guest reception rooms, supporting twelve participants without opening shared game-state reads or changing database rules. Private match payloads are sent to their authenticated recipient, while room summaries are broadcast.

Opening requests are bounded. Concurrent clicks, Back, cancellation, late completion, missing rooms and full rooms recover their controls. Message writes retain their IDs across retries, processed messages are deduplicated, and stale replies to a prior page session are discarded. A healthy empty database poll no longer hides a vanished browser. Guest claims retry heartbeat ETag conflicts instead of reporting an empty room as full, and explicit leave releases the seat.

## Operational scope

No new Firebase rules, accounts requiring a player login, paid service, new hosting project or changed public URLs are introduced. Anonymous transport identities and their refresh tokens stay in session storage. Tournament reception rooms expire after three minutes without the host heartbeat; explicit host close cleans them up. Polling is used, so background browser suspension can pause play and a prolonged interruption is reported.
