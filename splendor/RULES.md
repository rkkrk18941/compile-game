# 宝石の煌めき — ルールと出典

ボードゲーム「宝石の煌き（Splendor）」（作：マルク・アンドレ／Space Cowboys、日本語版：ホビージャパン）のルールで遊べる、個人用の非公式ブラウザ版です。絵・カードのデザイン・宝石の形はこのアプリのオリジナルで、原作のイラストは使っていません。

公開先：https://rkkrk18941.github.io/compile-game/splendor/

## 内容物（原作と同じ）

- 発展カード 90枚：レベルI 40枚、II 30枚、III 20枚。各レベルとも5色が同じ枚数（8／6／4枚ずつ）。
- 貴族タイル 10枚（すべて3点）：2色×4枚の条件が5枚、3色×3枚の条件が5枚。
- 宝石トークン：ダイヤモンド（白）・サファイア（青）・エメラルド（緑）・ルビー（赤）・オニキス（黒）各7枚、黄金5枚。

カード90枚と貴族10枚の数値（色・点数・コスト・条件）は、独立した3つの公開データ（`bouk/splendimax` の CSV、`seal256/splendor` の C++ データ、`Xe-Xo/SplendorML` の Python データ）を列の並びを合わせて機械的に照合し、**全件一致**したものを使っています（`tools/splendor-rules-test.mjs` に抜き取り確認あり）。もう1つ確認した実装（`boardgamers/splendor`）には転記の誤りがあり、採用していません。

## ルール（原作どおり）

| 項目 | 内容 | 出典 |
|---|---|---|
| 人数別の準備 | 2人：宝石各4・貴族3、3人：各5・貴族4、4人：各7・貴族5。黄金はいつも5。各レベル4枚を表向き | 英語版ルールブック、Board Game Arena のヘルプ、appmedia の解説 |
| 手番 | 次のどれか1つ：違う色3つを取る／同じ色2つを取る（その色が4つ以上あるとき）／1枚確保して黄金1つ／1枚買う | 同上、rules.dized.com |
| 確保 | 場の表のカードか山札の一番上（伏せたまま）。3枚まで。捨てられない（買うしかない）。黄金がなくても確保はできる | ルールブック、BGA |
| 購入 | ボーナス（購入済みカードの宝石）の分だけ安くなる。黄金は何色にもなる。支払ったトークンは場へ | 同上 |
| 補充 | 買った・確保した場のカードはすぐ同じレベルの山札から補充。山札が尽きたら空きのまま | ルールブック |
| 10枚制限 | 手番の終わりに黄金を含め10個まで。超えた分は好きなものを返す（取ったばかりのものも可） | ルールブック、rules.dized.com |
| 貴族 | 手番の終わりにボーナスが条件以上なら自動で来訪（3点）。トークンは数えない。1手番に1人、複数なら選ぶ。断れない。行動ではない | ルールブック、BGA |
| 終了 | だれかが15点以上になったら、そのラウンドを最後まで（全員の手番数が同じになるまで）遊んで終了 | ルールブック、BGA、GIGAZINE |
| 勝敗 | 点数（貴族を含む）が多い人。同点なら購入したカードが少ない人 | ルールブック、BGA、appmedia |

日本語版の用語（宝石トークン・黄金トークン・発展カード・貴族タイル・確保・威信ポイント）は GIGAZINE のレビュー記事の表記に合わせています。

## このアプリでの決めごと（ルールブックに書かれていないこと）

- **残っている宝石が3色未満のとき**：残っている色を1つずつ取れる（2色なら2つ、1色なら1つ）。ルールブックは「違う色3つ」としか書いておらず、よく使われる解釈（Geeky Hobbies の解説など）に合わせました。
- **支払い**：色の宝石を先に使い、足りない分だけ黄金を使う。黄金はどの色にもなるので、残しておくほうが損になることはありません。
- **パス**：宝石も確保も購入もできないときだけ。全員が続けてパスしたら終了して判定。
- **行き詰まりの防止**：12ラウンドのあいだ、だれもカードを買わず確保もしなかったら終了して判定（トークンの出し入れだけが続く膠着を終わらせるため。ふつうの対戦では起きません）。
- **完全な同点**（点数もカード枚数も同じ）：同率1位（引き分け）。
- **最初の番**：原作は最年少から。アプリでは「ランダム／あなた／CPU」を選べます。

## CPU

すべてのCPUは自分の席から見える情報だけで考えます（ほかの人が山札から伏せて確保したカードと、山札の順番は知りません）。

| 強さ | 考え方 |
|---|---|
| よわい | 目先だけを見る評価（先の計画・妨害なし）に、大きなゆらぎを入れて選ぶ |
| ふつう | つよいと同じ評価に、ほどほどのゆらぎを入れて選ぶ |
| つよい | すべての手を1手先まで試し、評価がいちばん高い手を選ぶ（自分の価値 − 最も有力な相手の価値） |
| かなりつよい | つよいの上位候補を、見えないカードを推定しながら先まで何百回も対局させて比べる（同じ推定を全候補に使う対比較と、順に候補を半分に絞る方式。約1秒） |
| 最強 | 情報集合モンテカルロ木探索。毎回見えないカードを推定し直しながら、自分と相手が交互に最善を選ぶ手の木を育て、1手に数千回の先読みで選ぶ。候補は評価の高い順に広げる（約3秒） |
| 成長する敵 | 最強から始まり、負けるたびに作戦の値を練習試合で学び直し、考える時間をふやす（PLAYROOM共通） |

評価関数は、点数、狙えるカードまでの手数（ボーナス・トークン・黄金・場の残りから計算）、貴族までの近さと競合、ボーナスの価値、持っているトークンの役立ち度などを組み合わせたもの。重みは自己対戦による山登り法で調整しています（`tools/splendor-tune.mjs`：1025案を試して33か所を採用、調整前の値に60.7%）。

### 強さの確認（同じ配りで席を入れかえた2人戦）

| 対戦 | 勝率 | 条件 |
|---|---|---|
| ふつう 対 よわい | 85.5% | 300局 |
| つよい 対 ふつう | 83.3% | 300局 |
| かなりつよい 対 つよい | 100%（60勝0敗、平均15.6点 対 9.0点） | 60局、かなりつよいの考える時間は本番の40% |
| 最強 対 かなりつよい | 72.5% ±6.6%（平均14.4点 対 12.6点） | 40局、両者とも考える時間は本番の50% |

参考：木探索にする前の最強（候補を並べて比べるだけの探索を長くしたもの）は、同じ40局でかなりつよいに55.0%でした。

## テスト

- `node tools/splendor-rules-test.mjs` — ルールの単体テスト（準備・取り方・確保・購入・10枚制限・貴族・終了と同点・パス・情報の隠し方・行き詰まり防止・CPUが合法手だけを打つこと）
- `node tools/splendor-ladder.mjs A B 組数 [時間倍率]` — CPUの強さ比較（同じ配りで席を入れかえた対局の組）
- `PLAYWRIGHT=... node tools/splendor-browser-check.mjs` — 画面からの通し対局、BGM一覧、続きから、各画面サイズ
