# 現実の街を下見する散歩

目的は、現地へ行く前に道路のつながり、坂、建物、公園や店舗の位置を把握すること。公開先は引き続き https://rkkrk18941.github.io/compile-game/tokyo-sora/ 。

## 今回実装した内容

- 地理院の標高・航空写真、PLATEAUの建物形状・実測高さ、OSMの道路・建物データを継続利用。
- OpenFreeMapの既存タイルからPOIを抽出。登録されたコンビニ、店舗、飲食店、駅、医療機関、学校、公園を実際の座標・名称・分類で表示。地下店舗は地上表示から除外し、上階の施設を1階の看板として描かない。
- 建物の外周内にある店舗だけに簡略看板を付ける。入口位置を捏造しない。建物と位置が一致しなければ施設情報として表示する。
- 近くの施設一覧に直線距離と方位を表示。選択で既存の目的地ガイドに接続。ミニマップにも実在施設を表示。遮蔽物の向こうに3Dラベルを表示しない。表示のオン・オフを保存。
- 公園・森林の実際の範囲に緑地と樹木を描画。parkポリゴンも取り込む。道路沿いの一律の架空街路樹と、建物シェーダーが生成していた架空商店・看板、根拠のない三角屋根を廃止。
- 人・車は、道路種別、土地利用、駅や店との距離、日本時間・平休日から推定。公園の歩道に車を出さず、高速道路や高架車道に歩行者を出さない。細かい道路分割が多い場所ほど人口が増えてしまう偏りを道路延長で補正。画質設定は描画数の上限。
- 最初は東京駅付近で徒歩開始。通常1.5m/s、走行4.5m/s。飛行・乗り物の機能は維持。

## 散歩機能の統合

- 標準は「街を散歩」。建物・人・車の破壊を抑止し、過去の破壊履歴を散歩景観に反映しない。履歴は「自由に遊ぶ」に戻した際に復元する。
- 道路タイル境界を高さも確認して接続。人・車の不自然な折返しを減らし、高架と地上道路を誤接続しない。
- 地上への移動は歩行可能な道と衝突形状から配置先を選ぶ。公園の道で道路外に押し出さない。
- 読込済みの歩ける道に沿って目的地までのルートを探索し、地上・ミニマップ・大きな地図へ表示。未読込や未接続の場合は直線案内と明記する。入口・私有地への通行可否までは保証しない。
- 大きな地図で実在施設とルートを確認し、目的地を選択。地図と航空写真も切替可能。
- 長い道路線分と緑地を標高に沿って細分化し、道の上の樹木を除外。細かな標高データが欠けても、取得済みの粗い地形を海抜0mで上書きしない。地図・標高・写真の取得期限を設け、通信停止で読込枠を占有し続けないようにする。
- 実景GLBと公開統計による交通補正の接続を実装。現時点で対応する実データは未統合。Claudeの成果物は[INTEGRATION.md](INTEGRATION.md)の形式へ合わせてから受け入れる。

## 確認方法

```
npm ci
node tools/test-tokyo-sora.mjs
node tools/test-tokyo-sora.mjs --live
npm run build:tokyo-sora
```

オフラインテストは実際に符号化したMVTをworkerへ渡し、店名と建物の対応、地下店舗の除外、公園・歩道の生成、車の進入制限、データ欠落時の動作を検証する。活動モデルについて、深夜と日中・駅前と住宅地の差、読み込み済み道路の長さによる抽選、道路の分割に対する不変性を検証する。

ライブ確認地点は東京駅、上野公園、読売ランド前。件数はその地点を含むz14タイル全域の件数であり、駅構内や徒歩圏の店舗数ではない。

## まだ完全再現ではない部分

- OSM未登録の店舗、更新前の閉店・建て替え、入口の向き・位置、店舗の実際の看板・窓・外壁は未再現。POIが登録されていないからといって、現地に施設がないとは限らない。
- 既存の23区PLATEAUタイルは2020年度のデータ。東京全域の最新建物・外観を保証しない。登録のない建物の高さは推定。航空写真と建物データにも撮影時期の差がある。
- 公園・森林の範囲は地図に基づくが、個々の樹木・街灯・道路幅は簡略表現。公園内部の設備、植生の個体位置、立入可否は網羅しない。
- 人流・車流は地図に基づくシミュレーションで、観測交通量や現在の混雑状況ではない。タイル境界の連続は対応済みだが、元の地図で交差点がつながっていない箇所、現地の信号制御、実際のバス路線はまだ再現していない。
- 今回の確認ブラウザはWebGL2非対応のため、GPUでの景観表示・スマートフォンの実機操作は未確認。ソースビルド、データ生成、地理情報とシミュレーションの回帰テストは別途確認。

## Claudeへ並行依頼する場合

同じファイルを同時変更すると衝突するため、以下は別ブランチで行い、mainへの直接pushはしない。生成物のindex.htmlは担当側では更新しない。実装時にはリポジトリ直下のAGENTS.mdを読む。

### 依頼A：実際の建物外観を描くためのデータ供給

> rkkrk18941/compile-game の東京そらさんぽを、現地の下見に使う散歩アプリへ改善しています。tokyo-sora/REAL_WORLD.mdとtokyo-sora/INTEGRATION.mdを読んでください。担当範囲は新規のtools/tokyo-sora-data/とtokyo-sora/data/以下のデータ作成パイプラインのみです。src/main.js、worker.js、city.js、shaders.js、index.htmlは変更しないでください。
>
> PLATEAU等の公式オープンデータから、テクスチャ付きLOD2以上の建物、地形、公園・道路の実形状を配信できる経路を調査・試作してください。公開利用条件、出典、年度、対象範囲、配信サイズ、座標系、欠損時の扱いを記録し、サンプル1地区で再現可能な変換コマンドと成果物を作成してください。利用できない情報をAI生成で補ったり、Google等の写真・ストリートビューを無断で一括取得しないでください。スマホで読み込める分割・LOD・メモリ予算が必要です。JSONマニフェストにはbbox・取得元・年度・座標系・データURL・ライセンスを含めてください。既存のPLATEAU/OSM描画に戻れる設計にしてください。別ブランチでPRにまとめてください。

### 依頼B：推定人流・車流を実測に近づける資料

> 担当範囲は新規のtools/tokyo-sora-traffic/とtokyo-sora/data/traffic/のみです。国交省道路交通センサス、自治体の歩行者通行量、鉄道駅の利用者数等の公式公開データから、地域別・時間帯別の推定モデルを較正するデータセットと更新スクリプトを作ってください。年度、観測地点、平休日、単位、実測/補間/推計、利用条件を機械可読に記録してください。日交通量をライブ混雑や歩行者数と誤表示しないこと。現行activity.jsに渡す座標付きの係数JSONと説明書までを成果物とし、既存srcやindex.htmlは変更しないでください。欠損地域は現行の地図由来の推定へ戻すこと。別ブランチでPRにまとめてください。
