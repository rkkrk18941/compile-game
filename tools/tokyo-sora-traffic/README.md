# 東京そらさんぽ：推定人流・車流を実測に近づける資料（依頼B）

国土交通省の**道路交通センサス**・**駅別乗降客数**、自治体の**歩行者通行量**などの公式公開データから、ゲームの「地図由来の推定」に掛ける座標付きの補正係数（`tokyo-sora/data/traffic/manifest.json`、`tokyo-sora/INTEGRATION.md` v1）を作る更新スクリプトです。

- ゲーム本体（`tokyo-sora/src/`・`index.html`）とルートの `package.json` は変更していません。係数は `src/integration.js` の `TrafficCalibration` がそのまま読みます。
- 人・車はあくまで**シミュレーション**です。係数は「公開統計で補正した推定」で、ライブの混雑・現在の人数ではありません。日交通量を時間交通量や歩行者数とみなしません。
- データの無い地域・曜日・種別は係数を作らず、ゲームは現行の推定を使います。

## 使い方

```sh
cd tools/tokyo-sora-traffic
npm ci
node update.mjs                     # 公式サイトから取得して tokyo-sora/data/traffic/ に manifest.json と records.json を作る
node update.mjs --dry-run           # 書き出さず、列の対応・件数・除外理由だけ表示（最初はこれで確認）
node update.mjs --prefs 13,14,11,12 # 対象の都県（既定は東京都・神奈川県）
node update.mjs --ped-csv 調査.csv   # 自治体の歩行者通行量（下記の共通形式CSV）を加える。複数可
node update.mjs --census-dir ./dl --s12 ./dl/S12-25_GML.zip   # ダウンロード済みのファイルを使う
node test.mjs                       # 検証（ネット不要）
```

取得したファイルは `.cache/`（git管理外）に保存し、URL・SHA-256 を `records.json` に記録します。

利用条件：道路交通センサスは国土交通省ウェブサイトのコンテンツとして**公共データ利用規約（第1.0版）**、国土数値情報は**CC BY 4.0**。どちらも出典と、加工した旨の記載が必要です（`sources.json` と `records.json` の `attribution`）。歩行者通行量は各調査の利用条件を CSV の license 列に書きます。

調べたが今回は使わなかったもの：全国の人流オープンデータ（1kmメッシュ, 国土交通省, 2019〜2021年）は、ダウンロードに G空間情報センターのログインが必要で、値がスマートフォンの位置情報から推計した滞在人口（歩行者数ではない）のため、組み込んでいません。

## 換算（`lib/coeff.mjs`）

ゲームは `推定 × factor` を使い、`factor` は 0〜4 の無次元・日本時間 0〜23時の24値です（INTEGRATION.md）。

- **時間変化の形**（センサス・歩行者通行量）：観測の時間別の量 `V(h)` と、推定の時間変化 `m(h)`（`src/activity.js` の `timeActivity`）から
  `factor(h) = (V(h) / Vの平均) / (m(h) / mの平均)`（0〜4に制限）。
  1日の総量は推定のまま（Σ factor·m = Σ m）で、「何時に多いか」だけを観測に合わせます。台数・人数そのものは推定の単位と対応しないので掛けません。観測の無い時間は 1。
- **駅の規模**（駅別乗降客数）：`factor = clamp(√(乗降客数 / 範囲内の駅の中央値), 0.25, 4)`（全時間同じ）。乗降客数は観測ですが、駅周辺の歩行者への換算は仮定なので `estimated`。
- 休日：センサスの公表表に休日の時間帯別交通量が無いので、車の `weekend` は作りません（休日は推定のまま）。
- 推定側（`activity.js`）の時間変化を変えたら、係数を作り直してください（`records.json` に使った曲線を記録）。

## 位置と半径

- センサスの観測地点は「交通量観測地点地名」（例：○○区○○１丁目）までしか公表されていません。国土地理院の住所検索で**丁目（半径250m）または町（半径400m）の代表点**にし、町名・丁目が一致しない場合と市区町村までしか分からない場合は使いません（`records.json` の `excluded`）。位置は数百m程度ずれることがあり、半径内のすべての道路に同じ形の係数がかかります。
- 駅：駅の位置（線）の重心、半径350m。歩行者通行量：CSV の緯度経度、半径150m（CSVで指定可）。
- 重なった地点はゲーム側で距離に応じた加重平均になります（掛け算で増えない）。

## 出力

| ファイル | 内容 |
|---|---|
| `tokyo-sora/data/traffic/manifest.json` | ゲームが読む係数（`{version:1, points:[{lat, lon, radius, basis, source, license, year, car?:{weekday}, ped?:{weekday, weekend}}]}`）。ゲームは2MiBを超えると読まないので、超える場合は止まります（`--bbox`・`--prefs` で狭める） |
| `tokyo-sora/data/traffic/records.json` | 地点ごとの元の値（単位付き）・観測日・観測区分・位置の決め方・換算式・係数、使った推定曲線、取得ファイルのURL/SHA-256、除外した地点と理由 |

## 歩行者通行量CSV（共通形式）

自治体の調査は公表形式がばらばらなので、元の表から次の列を写した CSV（UTF-8 か Shift_JIS）を作って `--ped-csv` で渡します。1行＝1地点・1時台の値です。

```
point_id,name,lat,lon,daytype,hour,count,unit,year,date,source,license,method,radius
ueno-01,上野駅前（例）,35.7138,139.7773,weekday,8,1234,人/時,2024,2024-10-08,○○区 歩行者通行量調査（URL）,○○区オープンデータ利用規約,人手計測,150
```

`daytype` は weekday/weekend、`hour` はその時台（8 = 8時台）。1時間ごとの値が6時間分以上ある地点・曜日だけ使います（12時間合計しか無い調査は形が分からないので使いません）。

## このPRの状態

この作業環境からは国土交通省・国土数値情報のサイトに接続できなかったため、**係数ファイル（manifest.json）はまだ生成していません**。ネットにつながる環境で `node update.mjs --dry-run` → `node update.mjs` を実行し、生成された `tokyo-sora/data/traffic/` をコミットしてください。それまではゲームは現行の推定のままです。

テストでは、国土交通省が公表した時間帯別交通量表（東京都）の実際の行で、列の順・時台の並び（7時台始まり）・12時間/24時間合計の検算を確認しています。箇所別基本表の CSV の見出しは公表資料の項目名から想定したもので、実ファイルで列を特定できない場合は列名の一覧を表示して止まります（`--dry-run` で確認できます）。
